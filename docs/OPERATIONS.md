# Эксплуатация

## Производительность и генерация сценариев

Приложение использует настройки пула PostgreSQL `DB_POOL_SIZE`, `DB_MAX_OVERFLOW` и `DB_POOL_TIMEOUT`. Базовые значения — `10`, `20` и `30` секунд; для стенда с большим числом пользователей их следует менять только после нагрузочного теста и проверки лимита соединений PostgreSQL. Мониторинг компонентов в `/api/operations` кэшируется на 3 секунды, поэтому частое обновление административной страницы не создаёт отдельную проверку всех сервисов на каждый запрос.

При `AI_MODE=rules` генерация сценариев полностью локальная и детерминированная: Ollama не требуется. Для типов ЕКП с готовым профилем используется профильный генератор; для остальных применяется безопасный шаблонный fallback. Такой сценарий всегда остаётся черновиком и требует проверки преподавателем. Режим `AI_MODE=ollama` следует включать только вместе с запущенным контейнером Ollama и загруженной моделью `OLLAMA_MODEL`; недоступность Ollama не должна блокировать базовую работу учебного контура.

После изменения этих параметров пересоздайте приложение:

```bash
docker compose up -d --force-recreate app
curl -fsS http://127.0.0.1:8001/health
```

Нагрузочные границы, измерения p50/p95, восстановление контейнеров и ограничения проверки физических SIP-телефонов описаны в [PERFORMANCE_TEST_2026-09-29.md](PERFORMANCE_TEST_2026-09-29.md).

Запуск: `docker compose up -d --build`. Состояние: `docker compose ps`; health: `/health`; логи: `docker compose logs -f app db`.

Мониторинг показывает текущую RAM процесса приложения в МБ и CPU за последнюю секунду в процентах. 100% CPU означает одно полностью занятое ядро; при использовании нескольких ядер значение может превышать 100%. Это показатели приложения, а не всего компьютера или суммы контейнеров.

## Резервное копирование

Сервис `backup` автоматически создаёт полную копию **каждые 23 часа** (`BACKUP_INTERVAL_HOURS`, допустимо 1–23). При первом запуске и после пропущенного интервала копия создаётся сразу. Ошибки повторяются автоматически; параллельные запуски защищены файловой блокировкой. Администратор может нажать «Создать резервную копию» в «Мониторинге»; запуск из терминала: `make backup` или `docker compose exec -T backup sh /backup.sh`.

Каждая папка `arm112_<время>_<идентификатор>` в `BACKUP_DIR` содержит:

- `database.dump`: PostgreSQL — пользователи, сценарии, занятия, карточки, результаты и аудит;
- `media.tar.gz`: аудио и записи звонков из тома `call_media`;
- `runtime.tar.gz`: вложения карточек и прочие пользовательские файлы из `app_data`;
- `SHA256SUMS` и `manifest.json`: контрольные суммы, время и общий размер.

Копия публикуется после успешной проверки всех файлов. Неудачный запуск сохраняет предыдущую копию. `latest.bundle` указывает на последнюю полную папку; `latest.dump` оставлен для совместимости старого восстановления БД. Копии хранятся 180 дней. Мониторинг показывает суммарный размер в МБ, свежесть и ход выполнения; копия старше 24 часов считается устаревшей. Healthcheck контейнера проверяет свежесть, комплектность и доступность планировщика.

В «Мониторинге» раскройте «Резервные копии»: список показывает дату/время в часовом поясе браузера, состав, полный размер, размер БД и готовность. Старые отдельные дампы помечены «Только БД», временные и служебные файлы скрыты. «Скачать БД» доступно только администратору и записывается в аудит; скачивается PostgreSQL custom-format `.dump`, **без аудио и вложений**. «Скачать всё» сохраняет полную копию одним `.tar.gz`: PostgreSQL, записи звонков, кэш озвучивания и вложения. Ссылка на скачивание одноразовая и действует 10 минут; большие файлы браузер скачивает напрямую.

### Перенос на новый сервер одним файлом

1. Завершите звонки на исходном сервере. Администратор открывает «Мониторинг», создаёт свежую копию, ждёт завершения и нажимает «Скачать всё» у этой копии.
2. На новом компьютере запустите ту же версию приложения по инструкции README. Настройки `.env`, адреса SIP и Docker-образы не входят в архив: задайте параметры нового компьютера. Не публикуйте скачанный архив — он содержит пользователей и их данные.
3. Войдите администратором новой установки, откройте «Мониторинг → Загрузить копию», выберите `.tar.gz` и подтвердите восстановление текущим паролем администратора новой установки.
4. После успеха войдите с логином и паролем из перенесённой базы. Пользователи, карточки, занятия, ответы, оценки, история, записи и вложения восстановлены из снимка. Незавершённые звонки закрываются, активные задачи генерации отменяются; прежние сессии аннулируются.
5. Проверьте историю и прослушивание записи. Переподключите SIP-телефоны с обновлёнными паролями и IP нового сервера из инструкции подключения. Проверьте мониторинг компонентов.

### Восстановление из кабинета администратора

В раскрытом списке нажмите «Восстановить всё» для полной копии или «Восстановить БД» для замены только PostgreSQL. Для переноса с другого сервера раскройте соседнюю панель «Загрузить копию», выберите скачанный `.tar.gz` и нажмите «Загрузить и восстановить». Полный архив ограничен 2 ГБ, распакованные аудио и вложения — 8 ГБ; нужны свободное место для проверки и временных копий файлов. Отдельный `.dump` заменяет только БД. Поддерживается PostgreSQL custom-format (`PGDMP`), до 100 МБ; SQL, ZIP и дампы с дополнительными исполняемыми объектами не принимаются. На обоих серверах должны быть совместимые PostgreSQL 16 и одинаковая структура текущей версии приложения.

Подтвердите доверенный источник, введите текущий пароль администратора и слово **ВОССТАНОВИТЬ**. Это заменяет всю БД: пользователи, занятия, карточки и результаты, добавленные после выбранного снимка, исчезнут. После замены нужны учётные записи и пароли из восстановленной базы. PostgreSQL предупреждает, что восстановление может исполнять код исходной базы; импортируйте только копии с доверенного сервера ([документация PostgreSQL](https://www.postgresql.org/docs/16/app-pgrestore.html)).

Процесс выполняется в фоне:

1. Новые API-операции блокируются; ранее начатые запросы завершаются. Активные звонки и задания генерации необходимо завершить до запуска.
2. Для полной копии проверяются комплектность, SHA-256, gzip, размер и безопасные пути всех файлов. Ссылки и пути за пределами каталога отклоняются. Проверяются формат и неизменность файла; дамп реально восстанавливается в промежуточную базу под временной ролью без прав суперпользователя и создания баз/ролей.
3. Проверяются структура таблиц и наличие незаблокированного администратора. Ошибочный дамп оставляет рабочую базу нетронутой.
4. Создаётся свежая **полная копия текущей БД, аудио и файлов**. Её имя показано в результате восстановления и она доступна в списке копий.
5. При полной копии заменяются аудио и вложения; прежние файлы удерживаются до завершения операции, а при неудаче до переключения БД возвращаются автоматически. Журнал позволяет продолжить возврат после перезапуска. Подключения к рабочей базе закрываются, проверенная и прежняя базы переключаются одной транзакцией. Исходная база сохраняется до завершения подключения приложения; затем удаляется, страховочная копия остаётся на 180 дней.
6. Старые сессии аннулируются, незавершённые звонки/задачи из снимка закрываются. SIP-пароли обновляются, Asterisk перезапускается при наличии соединения. Войдите заново и переподключите браузерные и аппаратные телефоны; аппаратные пароли нужно взять из новой инструкции подключения.

После завершения автоматически запрашивается полная копия восстановленного состояния; страховочная копия прежнего состояния сохраняется отдельно.

В диалоге отображается текущий этап. Обновление страницы сохраняет наблюдение за заданием в этой вкладке. Запрос и успешное восстановление записываются в аудит; закрытые журналы заданий находятся в `BACKUP_DIR/restore_jobs`, загруженные дампы — в `BACKUP_DIR/uploads`. После успешного импорта загруженный файл удаляется; неиспользованный импорт доступен 24 часа.

**«Восстановить БД» заменяет только PostgreSQL**, как для сохранённой копии, так и для загруженного дампа. Текущие файлы сохраняются на сервере. При импорте загруженного дампа старые `recording-*.wav` перемещаются в `/media/before_database_import/<job_id>`: разные серверы используют одинаковые числовые ID, поэтому местная запись не должна подставляться к чужой импортированной карточке. Кэш синтеза и вложения остаются. Для переноса истории вместе с файлами выбирайте «Скачать всё» и импорт `.tar.gz`, либо «Восстановить всё» у сохранённой полной копии. Само приложение нельзя выключать во время завершения операции: оно подключает восстановленную базу и завершает задание. После перезапуска обработчик проверяет состояние и повторяет незавершённый этап; если завершение не проходит, режим обслуживания остаётся включённым для защиты данных. Смотрите `docker compose logs app backup`, не снимайте блокировку вручную без проверки базы.

Проверка восстановления: `make verify-backup` или `docker compose exec -T backup sh /verify.sh`. Проверяются SHA-256, PostgreSQL действительно восстанавливается в отдельную временную базу, файловые архивы распаковываются в отдельный временный каталог. После проверки база и каталог удаляются; рабочая база не изменяется. Дата успешной проверки видна в мониторинге (с указанием, относится ли она к текущей копии).

**По умолчанию копии локальные**, `BACKUP_DIR=./backups`. Для защиты от отказа диска укажите каталог на отдельном накопителе или подключённом NAS в `.env`, затем пересоздайте `backup` и `app`: `docker compose up -d --force-recreate backup app`. Права записи должны быть доступны обоим контейнерам. Для второй копии включите `BACKUP_MIRROR_ENABLED=1` и укажите `BACKUP_MIRROR_DIR` на отдельный диск/NAS; после успешной публикации локального backup сервис атомарно копирует туда полный bundle и обновляет `latest.*`. Проверочная распаковка в отдельную временную БД выполняется раз в `VERIFY_BACKUP_INTERVAL_HOURS` (по умолчанию 168 часов). Пароли и персональные данные входят в дамп: ограничьте доступ к каталогам; копии не включаются в Git. Настройки развёртывания `.env`, Docker-образы и модели следует хранить отдельно в защищённом месте.

Для аварийного восстановления остановите `app` и `asterisk`, выберите проверенную папку копии, восстановите `database.dump` штатным `pg_restore` в PostgreSQL и распакуйте `media.tar.gz` в `call_media`, `runtime.tar.gz` в `app_data`, затем запустите сервисы. Предпочтительно восстанавливать в новый пустой контур. `make restore` выводит ссылку на инструкции и само данные не изменяет. Рабочее восстановление может перезаписать данные; для безопасной проверки предназначен `make verify-backup`.

Копирование выполняется без остановки приложения: PostgreSQL использует согласованный снимок БД; запись звонка, ещё продолжающегося во время копирования, может попасть в архив незавершённой. Строгое согласование БД и файлов требует остановки обработки на время копии. Удаление карточек и пользователей, а также плановая очистка старых данных теперь блокируются до появления свежей полной копии; при этом backup автоматически ставится в очередь.

### Политика хранения

Проектная политика устанавливает хранение карточек, результатов, аудио и аудита **180 дней (6 месяцев)**. Приложение выполняет очистку при старте и раз в сутки; администратор может вызвать её вручную из API мониторинга. Удаляются связанные события, отзывы, записи и файлы. Для планирования используйте около 0,96 МБ на минуту моно WAV-записи 8 кГц/16 бит; аудио обычно занимает больше места, чем карточки и аудит.

Администратор может удалить пользователя из кабинета. Удаление пользователя удаляет его карточки, связанные аудио, SIP-учётную запись, занятия и экспертные записи; сценарии, созданные преподавателем, остаются без владельца. В журнале карточек администратор может удалить отдельную карточку вместе с событиями и аудио. Оба действия требуют подтверждения и записываются в аудит.

Обновление: собрать версионированный image, выполнить миграции, переключить сервис после healthcheck. Текущий MVP использует `create_all`; перед production добавить Alembic и версионированные миграции.

Offline: экспортировать все Docker images (`docker save`), Python wheels при необходимости, AI model files и проверенные checksum. Не полагаться на внешние registry в целевом контуре.

## Источники и обновление

При старте импортируются XLSX из source_materials и data/imports/tickets.json. SHA-256 различает версии; старые версии и сессии сохраняются. Для применения замены источника: docker compose up -d --build. Неподдерживаемая структура XLSX отклоняется.

Повторное локальное OCR: make ocr, затем пересборка приложения. Отдельный контейнер Poppler/Tesseract не нужен базовой системе; в изолированный контур его привозят заранее. Все задачи требуют проверки преподавателем.

make test использует отдельный контейнер и временную SQLite, не очищает рабочую PostgreSQL. Новые таблицы добавляются без удаления старых данных; перед обновлением выполните backup.

### Обращения о проблемах

«Сообщить о проблеме» отправляет описание, при необходимости скриншот и номер текущей карточки. В меню администратора отдельный пункт **«Обращения»** показывает счётчик новых заявок и выделяется, пока есть новые. По умолчанию открываются новые обращения; фильтр позволяет посмотреть все или выбрать статус.

Администратор выбирает **«Новое», «Сделано», «Отменено» или «Ложное»**, добавляет комментарий и нажимает **«Сохранить»**. Статус «Новое» позволяет вернуть обращение в работу. В обращении видны автор, время отправки, карточка, скриншот и кто/когда обработал заявку. Автор через **«Мои обращения»** видит только собственные заявки, их статус и комментарий администратора.

Изменения сохраняются в PostgreSQL как события `issue.review` с ID обращения, статусом и комментарием. Эти события служат постоянным состоянием обращения и не удаляются обычной очисткой аудита через 180 дней; прочие события сохраняют прежний срок хранения. История изменений и состояние обращений входят в резервные копии БД; скриншоты — в полную копию. Структура БД не меняется, ранее созданные копии совместимы.

### Подготовка практического занятия

У преподавателя откройте «Занятия → Создать занятие». На странице сначала показаны подготовленные, активные и завершённые занятия; фильтр позволяет выбрать нужный статус. Состав заданий и участники раскрываются в карточке занятия.

1. Назовите занятие и выберите приём вызова 112 или реагирование ДДС. Для ДДС выберите службу по названию: показываются задания, в исходных карточках которых есть эта служба. В режиме 112 поле службы скрыто.
2. Найдите свои утверждённые задания по названию, категории или тексту, при необходимости отфильтруйте сложность. «Посмотреть» открывает реплику, норматив и эталон без перехода к редактированию сценария. Выбранные задания показаны отдельно; поиск их не снимает.
3. Выберите студентов, используя поиск и «Выбрать найденных». Проверьте итоговое число заданий и участников, нажмите «Назначить занятие».

Черновик автоматически сохраняется в **этой вкладке браузера отдельно для каждого преподавателя**: переходы между разделами и обновление страницы не сбрасывают название и выбор. Это ещё не назначенное занятие и не серверное сохранение. «Закрыть» скрывает форму, «Продолжить подготовку» возвращает её; «Сбросить черновик» очищает подготовку. Если режим/служба изменились или задание стало недоступно, его выбор сохраняется, но нужно убрать неподходящее задание перед сохранением.

Подготовленное занятие можно редактировать кнопкой «Редактировать». После запуска или завершения состав менять нельзя; нужно подготовить новое занятие. «Начать занятие» открывает задания студентам, «Мониторинг и отчёт» показывает работу. «Следующая карточка» выдаёт случайное оставшееся задание, завершённые повторно не выдаются; студент также может выбрать конкретное задание из списка. «Завершить занятие» завершает текущие обработки с сохранением результатов.

### Билеты из PDF и доступ студентов

У преподавателя и администратора появился отдельный пункт меню **«Билеты и задачи»**: все 32 исходных билета, 96 задач. Поиск работает по номеру и тексту. «Оригинал» у задачи открывает соответствующую страницу PDF; «Оригинал билетов» — весь документ. Преподаватель нажимает «В сценарий», проверяет OCR-текст и эталон, затем утверждает сценарий и включает его в занятие. Импорт исходных задач не означает автоматическую выдачу их всем студентам.

Студент видит только сценарии назначенных ему занятий либо отдельного задания, явно отправленного преподавателем через SMS. До первого назначения список пустой. Подготовленное назначенное занятие и его задания видны заранее; начать обработку можно после запуска преподавателем. Полный PDF билетов и каталог исходных задач студенту недоступны, включая прямые API-запросы. Прямой запуск и подготовка озвучки чужого/неназначенного сценария блокируются сервером. История собственных результатов сохраняется. Старые открытые обработки без действующего назначения закрываются без оценки, с сохранением полей и накопленного времени, чтобы не мешать новым заданиям.

### Заготовки занятий

В «Занятиях» назовите подготовку, выберите задания и нажмите **«Сохранить заготовку»**. Студентов можно пока не выбирать. Заготовка сохраняется **в БД сервера**, входит в резервную копию и доступна через **«Мои заготовки»** после входа с другого браузера. Это отличается от автоматического черновика формы, который хранится только в текущей вкладке.

Заготовку можно редактировать в любое время: менять название, задания, добавлять и убирать студентов. Даже указанные в заготовке студенты не получают доступа, пока преподаватель её не выдаст. Для выдачи откройте «Выдать студентам», проверьте группу и нажмите **«Назначить занятие»**. Создаётся отдельное подготовленное занятие с выбранным составом; нажмите «Начать занятие», чтобы студенты приступили.

Одна заготовка используется многократно. Изменение названия, списка заданий или группы в заготовке не меняет ранее назначенные занятия. У выданного подготовленного занятия состав можно менять до старта; после старта он защищён. Редактирование самих сценариев, уже используемых в активных занятиях, по-прежнему ограничено, чтобы не менять эталон во время работы студентов.

### Группировка результатов и экспорт за период

В разделе «Результаты обучения» преподаватель выбирает «По студентам», «По датам» или «Общий список». Группы раскрываются нажатием на заголовок; рядом показаны число попыток, завершений, пропусков и средний первичный балл. Пропущенные и ещё не оценённые попытки не входят в средний балл. «Разбор» открывает ответы, историю и записи выбранной попытки.

Фильтры «Студент», «С даты» и «По дату включительно» одновременно ограничивают список и «Экспорт CSV». Период определяется датой начала обработки; границы календарных дней учитывают часовой пояс браузера. Чтобы скачать, например, результаты за месяц, сначала задайте обе даты, затем нажмите «Экспорт CSV». Без дат экспортируется весь доступный период. «Сбросить фильтры» возвращает все доступные результаты. Преподавателю по-прежнему доступны только его результаты, студенту — только собственные.

При нажатии «Редактировать» в списке сценариев страница автоматически прокручивается к заполненной форме выбранного сценария. Фокус переходит на заголовок редактора; стрелка назад возвращает к списку.

### Поиск в журнале преподавателя

В основной строке поиска журнала доступны «Студент», «С даты» и «По дату включительно». Их можно сочетать с номером, типом, адресом или описанием карточки, затем нажать «Найти». Выбор другого студента сразу обновляет журнал и возвращает первую страницу. Период определяется началом обработки, в часовом поясе браузера; последний выбранный день включён полностью. Фильтры действуют при перелистывании и автообновлении. «Сбросить» очищает строку, студента, даты и дополнительные параметры. Студент видит свой журнал без выбора чужой учётной записи; права преподавателя ограничивают поиск его занятиями и сценариями.

Кнопка «Создать новую карточку» в верхней панели предназначена только для студента: она открывает его рабочее место и список назначенных заданий. Преподавателю для подготовки заданий нужен раздел «Сценарии», а для выдачи — «Занятия». У преподавателя и администратора кнопка создания студенческой карточки скрыта.

### Русскоязычный словарь озвучки

Общая обработка словарём отключена после замечаний по качеству. В активной озвучке группы телефонных номеров читаются русскими числительными, а группы с ведущим нулём — по цифрам с сохранением всех нулей, а явно указанные адресные номера — русскими числительными; произвольные количества, даты и сложные адреса не заменяются. Также действуют проверенные фразы «с того же но́мера» и «с этого же но́мера». Исходный сценарий и выбор голоса сохраняются; прежние записи не меняются. Экспериментальный словарь, источники и ограничения описаны в [PRONUNCIATION.md](PRONUNCIATION.md).
