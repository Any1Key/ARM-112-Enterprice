Этот файл нужен для продолжения разработки после перезапуска компьютера или новой сессии Codex. Перед изменениями прочитать этот файл, затем `README.md`, `docs/DDS_TRAINING.md` и документы, относящиеся к задаче. Файл не содержит действующих паролей и секретов.

## Репозиторий и ветки

- GitHub: `https://github.com/yaro-s-lav/hacka.git`.
- Актуальная ветка разработки кабинета ДДС: **`dds`**.


  Изменения сначала выполняются и проверяются в `/opt/hacka/arm112_trainer`, затем только изменённые исходники и документация копируются в checkout, проверяются через `git diff --check`, коммитятся и отправляются в `origin/dds`. Не переносить в Git рабочую `.env` с настоящими секретами, базу, резервные копии, аудиозаписи и временные проверочные скрипты из `/tmp`.

## Запуск актуальной версии ДДС

На новом компьютере:

```bash
git clone --branch dds --single-branch https://github.com/yaro-s-lav/hacka.git
cd hacka
docker compose --profile voip --profile ai up -d --build
docker compose --profile voip --profile ai ps
curl http://localhost:8000/health
```

Открыть `http://localhost:8000`. Обычный запуск только базовых сервисов: `docker compose up -d --build`. Для звонков ДДС нужны профили `voip` и `ai`: Asterisk, голосовой сервис и локальные вспомогательные сервисы.

После перезагрузки уже развёрнутого компьютера из `/opt/hacka/arm112_trainer`:

```bash
docker compose --profile voip --profile ai up -d
docker compose --profile voip --profile ai ps
curl http://localhost:8000/health
```

Не выполнять `docker compose down -v`: ключ `-v` удаляет тома с базой и данными. Подробности: `README.md`, `docs/OPERATIONS.md`, `docs/SIP_PHONE_SETUP.md`.

## Назначение кабинета ДДС

Режим `dds` моделирует этап после оператора 112:

1. Система передаёт студенту уже заполненную карточку 112.
2. Видит свою службу и остальных получателей карточки; поля карточки и список служб не редактирует.
3. Принимает карточку либо отклоняет с причиной, затем ведёт статусы своей службы с комментариями до завершения.
4. При необходимости связывается с заявителем, бригадой или другой службой обычным телефоном, другим каналом или через стороннее ПО; в тренажёре фиксирует контакт и результат.
5. Преподаватель видит решение, статусы, комментарии, журнал контактов, время и оценку.

Таймер новой ДДС-карточки начинается с запуска занятия и продолжает идти в очереди. В звонке заявителю диспетчер говорит по сути обращения, номер карточки обычно не называет.

Это отдельный кабинет от первоначального приёма звонка 112. Прежний режим `dispatch` также сохраняется.

## Что реализовано в ДДС и история прежнего режима

- Преподаватель создаёт 1–100 карточек по нескольким категориям ЕКП.
- Источники: системные карточки, завершённые карточки своих студентов или смешанный набор.
- Варианты новых занятий: карточка направлена своей службе по назначению либо ошибочно направлена не той службе.
- Исходная карточка попытки неизменна; новые попытки не разрешают студенту менять поля или добавлять службы.
- Студент видит только назначенные ему занятия и карточки. Эталон скрыт.
- Задание можно пропустить и вернуться; в новых занятиях ДДС время продолжает идти и в очереди. Завершённые задания повторно не запускаются.
- После завершения автоматически выдаётся следующая карточка активного занятия.
- Преподаватель может остановить занятие; незавершённые действия попадут в отчёт.
- Оценка новых попыток: решение своей службы — 35, статусы — 25, комментарии — 20, время первой реакции — 20.
- Старые попытки проверки карточки и их оценки сохраняются в истории со старым форматом отчёта.
- Исторические SIP-вызовы и записи старых попыток остаются в полном разборе. Новые контакты с заявителем, бригадой и другими службами журналируются как внешние; вызов на обычный номер тренажёр не выполняет.

Главная инструкция: `docs/DDS_TRAINING.md`.

Новые материалы `source_materials/112card.docx` и `source_materials/112service.docx` (25.09.2026) состоят преимущественно из снимков экрана 112. Они подтверждают, что карточку и список получателей заполняет оператор 112; адресного справочника ДДС и телефонов служб в них нет. Разбор: `docs/SOURCE_REVIEW.md`.

Презентации `1694552.pptx`, `1710720.pptx`, `1755040.pptx` от 28.09.2026 посвящены интерфейсу карточки/журнала 112, реестру заявителей и управлению сменами. Последние два модуля не относятся к полномочиям ДДС и содержат открытые вопросы; полного территориального справочника в презентациях нет. Визуальный разбор и границы применения — в `docs/SOURCE_REVIEW.md`. Журнал 112 теперь использует один блок расширенного поиска с более читаемыми строками на широком экране.

## Заготовки и интерфейс преподавателя

- В «Карточках ДДС» есть отдельный список заготовок.
- Заготовку можно создать и назвать без выбора студентов, выбрать задания и свою службу.
- Её можно редактировать, добавлять и удалять билеты, затем многократно назначать разным группам.
- Каждое назначение создаёт отдельное занятие; изменение заготовки не переписывает уже назначенные занятия.
- После генерации карточек есть «Создать заготовку из набора».
- Для 112 доступна та же схема через «Создать заготовку без студентов».
- Меню преподавателя сгруппировано: занятия и результаты; подготовка карточек; история и помощь.
- По входу преподаватель открывает раздел занятий.
- Редакторы занятий, заготовок и сценариев 112 открываются в модальном окне поверх списка. Заголовок и действия закреплены; после закрытия сохраняется место списка.
- В разборе есть отдельные действия «Сохранить оценку и комментарий» и «Закрыть без сохранения». Закрытие не отправляет изменения.

## Генерация, голоса и грамматика

- Генерация сценариев строится правилами и каталогами приложения; Qwen может использоваться как дополнительный компонент, но не является единственным источником текста.
- После генерации выполняются проверки связности: объект, адрес, город, метро/аэропорт/вокзал, телефон, факты и повторы.
- Телефонный формат: `+7 9xx xxx xx xx`. Группы с ведущим нулём читаются по цифрам; обычные двузначные группы — числом.
- Голос выбирается с учётом пола имени; исключённые ранее некачественные варианты не возвращать без проверки.
- Технические пометки в квадратных скобках удаляются перед TTS и не должны зачитываться.
- Правило LanguageTool `UPPERCASE_SENTENCE_START` отключено. Регистр первой буквы не считается ошибкой; остальные орфографические замечания сохраняются.
- Подробности произношения: `docs/PRONUNCIATION.md`.

## Отчёты, данные и резервные копии

- Отчёты фильтруются по студенту и датам, группируются по студентам или дням. CSV использует тот же период.
- Разбор новых попыток ДДС хранит исходную карточку, решение своей службы, статусы, комментарии и журнал контактов. История старых попыток хранит прежние исправления, передачи и SIP-записи.
- PostgreSQL хранит пользователей, сценарии, заготовки, занятия, попытки, события, оценки и SIP-метаданные.
- Аудио и вложения лежат в файловом хранилище Docker и входят в полную резервную копию.
- Полный `.tar.gz` переносит базу, аудио и вложения. Отдельный дамп БД не переносит файлы.
- В админке есть создание, скачивание, проверка и восстановление копий. Версия приложения при восстановлении должна совпадать.
- Подробности: `docs/OPERATIONS.md`.

## Важные технические файлы

- `app/dds.py` — проверка карточки, передачи и оценка ДДС.
- `app/dds_telephony.py` — исходящие учебные SIP-вызовы ДДС.
- `app/workflows.py` — занятия, заготовки, выдача и завершение попыток.
- `app/report_details.py` — полный разбор и метаданные звонков.
- `app/static/dds.js` — кабинет ДДС.
- `app/static/lesson-editor.js` — занятия и заготовки.
- `app/static/reports.js` — отчёты, звонки и воспроизведение.
- `app/static/teacher-navigation.js` — меню преподавателя и модальные редакторы.
- `deploy/asterisk/extensions.conf` — маршруты и MixMonitor.
- `tests/test_dds.py` — интеграционные проверки ДДС.

## Проверки перед публикацией

Минимум:

```bash
node --check app/static/dds.js
node --check app/static/lesson-editor.js
node --check app/static/reports.js
node --check app/static/teacher-navigation.js
python3 -m compileall -q app
docker compose run --rm --no-deps \
  -v "$PWD/tests:/app/tests:ro" \
  app python -m pytest tests/test_dds.py tests/test_report_details.py -q
docker compose --profile voip --profile ai up -d --build
docker compose ps
curl http://localhost:8000/health
```

Для интерфейсных изменений нужна браузерная проверка реального пользовательского пути. Тестовые пользователи, занятия и заготовки после проверки удалять строго по уникальному префиксу и владельцу; не затрагивать существующие данные.
