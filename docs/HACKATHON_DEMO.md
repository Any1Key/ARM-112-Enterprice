# Демонстрация тренажёра

## Запуск

```bash
git clone https://github.com/yaro-s-lav/hacka.git
cd hacka
docker compose --profile ai --profile voip up -d --build
```

Открыть `http://localhost:8000`. Docker скачивает образы и русские голоса при первой сборке; последующие запуски используют локальные данные. Учебные пользователи: `student`, `teacher`, `admin`; пароли соответствуют значениям в `.env`, в опубликованном демо — `student12345`, `teacher12345`, `admin12345`.

Карточки устанавливаются из каталогов `data/scenarios/practice.json` и `data/scenarios/workflows.json`. Импорт повторяемый, правки преподавателя сохраняются. ЕКП по умолчанию — явно выбранный `046_24`, 1283 типа и 24 группы. Другой XLSX в папке не влияет на запуск; для 90-колоночной редакции есть отдельное сопоставление колонок.

## Сценарий показа на 5–7 минут

1. **Студент, карточка 112.** Открыть «112 · пожар · несколько объектов и пострадавшие». Показать автоматический АОН. Выбрать опросную карту пожара, место/объект/признаки, указать этажность и этаж пожара; выбрать квартиру и подъезд одновременно. Отметить двух пострадавших и угрозу людям. Показать автоматическое появление 103 и происхождение служб из ЕКП.
2. **Сохранение и дополнение.** Заполнить адрес и описание, подтвердить сохранение и оповещение. Время создания остановится. Нажать «Дополнить карточку», уточнить описание или ранее пустое поле. ФИО и статус заявителя после регистрации менять нельзя; дополнение видно в истории.
3. **Учебная пауза.** Пропустить карточку, открыть другую, вернуться к первой. Сведения и накопленное время сохраняются, история показывает пропуск и возобновление. Пауза не прибавляется к времени создания.
4. **Особые случаи.** Открыть метро — место задано станцией и платформой, без вымышленного дома. Открыть карточку без контакта и сохранить пустую карточку с соответствующим флагом: она завершена и проверена. Для повторного обращения показать совпадения и связь с главной карточкой.
5. **Преподаватель и ДДС.** В отдельном окне войти как преподаватель. Назначить занятие с «ДДС · пожар · от принятия до завершения», выбрать службу из списка оповещения, запустить занятие. Студент принимает поступившую карточку, последовательно указывает реагирование, наряд, комментарий и завершение. Преподаватель видит действия и отдельное время реакции.
6. **SMS.** Преподаватель в разделе занятий отправляет учебное SMS по сценарию «112 · SMS · человек без сознания». Отправка преподавателем назначает выбранный утверждённый сценарий этому студенту независимо от других занятий. Студент без активной карточки выбирает статус «Доступен», принимает сообщение. АОН, текст и предоставленные координаты заполняются автоматически. Показать историю и ответ. Сообщения остаются внутри учебной системы.
7. **SIP и оценка.** Подключить браузерный телефон, запустить учебный звонок, принять и прослушать. Показать запись, исходящий вызов в учебную службу и отчёт с проверкой ответов опросной карты. Преподаватель может добавить экспертную оценку.

При наличии активного назначенного занятия студент видит сценарии этого занятия. Для самостоятельного показа использовать отдельного демо-студента без назначений либо назначить необходимые карточки в одно активное занятие.

## Браузерный и аппаратный SIP

В браузере localhost работает с микрофоном по HTTP. На другом компьютере для браузерного микрофона использовать HTTPS-контур `https://<сервер>:8443` с доверенным сертификатом.

В панели телефона раскрыть «SIP / IP-телефон · функции». Кнопка «SIP-телефон» показывает регистрационные данные **текущего студента**. Браузер использует отдельный WebRTC-аккаунт `arm<ID>`, аппарат — `arm<ID>-hw` по UDP/5060. Регистрации не вытесняют друг друга.

Для РТУ Т16Р или другого SIP-аппарата в той же сети:

[Подробная инструкция с примером IP-адресов, коротким паролем и устранением проблем](SIP_PHONE_SETUP.md).

1. Указать LAN-IP компьютера с Docker в `SIP_PUBLIC_ADDRESS` в `.env`. Например, если IP компьютера `192.168.1.20`, установить `SIP_PUBLIC_ADDRESS=192.168.1.20`.
2. Пересоздать компоненты:

   ```bash
   docker compose --profile voip up -d --force-recreate asterisk
   docker compose up -d --force-recreate app
   ```

3. Создать SIP-линию аппарата: сервер — этот LAN-IP, порт 5060, транспорт UDP, имя/Auth ID и пароль — из кнопки «SIP-телефон». Предпочтительные кодеки G.711A/G.711U, при наличии G.722. Для этого локального профиля SRTP отключён.
4. Набрать `900` для проверки звука. Кнопка «Звонок на аппарат» направляет озвученную реплику открытой карточки на этот аппарат.

Исходящие `101`–`104` соединяют с **учебными** диспетчерами; они не звонят в реальные экстренные службы. Поддерживаются микрофон, удержание, громкость, перевод текущего учебного вызова и изолированная конференция до четырёх участников. Номер конференции выдаёт приложение; войти может второй терминал той же учётной записи. Реальные операторы внешних служб и городская телефонная сеть не подключены.

Аппаратный профиль и регистрация программным SIP-клиентом могут быть проверены без физического Т16Р; совместимость самого аппарата, его клавиш и сети подтверждается испытанием на устройстве.

## Соответствие источникам и границы

Опросные карты покрывают 24 группы и все 1283 типа действующего ЕКП. Признаки и условные службы берутся из XLSX. Подробные учебные вопросы пожара, газа и взрыва сверены с новыми изображениями; остальные формы расширены учебными вопросами по условиям ЕКП. Это не утверждение, что восстановлены все около 50 оригинальных промышленных шаблонов: полный структурированный комплект в источниках отсутствует.

Карта — локальная схема координат с выбором точки и радиуса. Реальные адресные справочники, территориальные полигоны, камеры и техника заказчика не предоставлены. Приложение не изображает их подключёнными. SMS, службы, обращения о проблемах и запросы помощи демонстрируются внутри учебной среды; промышленная ПОВ-112 и внешние ВИС не подключены.

Нагрузочные результаты, если получены, относятся к указанному стенду и конкретному виду запросов. Они не заменяют испытания целевого оборудования, отказоустойчивости и всего процесса со 100 пользователями.

## Памятка студента

Раздел «Памятка» содержит встроенное руководство по тренажёру, включая задания, таймер, пропуск/возврат, карточки 112 и действия ДДС. Оригинальная PDF-памятка для ДДС открывается в просмотрщике на странице, доступна для скачивания и открытия в новой вкладке. Билеты с исходными заданиями остаются в кабинете преподавателя. [Текст руководства](STUDENT_GUIDE.md).

## Резервные копии и перенос БД

В кабинете администратора откройте «Мониторинг»: рядом расположены раскрывающиеся панели «Резервные копии» и «Загрузить копию». Покажите дату/состав/размер копий, «Скачать всё» (`.tar.gz` с БД, аудио и вложениями) и отдельное скачивание `.dump` и диалог восстановления с текущим паролем администратора и подтверждением. Полное восстановление на демонстрации выполняйте только в отдельном контуре: рабочие пользователи, карточки и результаты заменяются. Проверяется дамп в промежуточной базе, сохраняется полная копия до замены, затем требуется новый вход и подключение телефонов. Полная копия переносит аудио и вложения вместе с БД; `.env` и IP нового сервера задаются отдельно.

Проверка на отдельной PostgreSQL-базе подтвердила отклонение повреждённого дампа без потери данных, корректное восстановление загруженной копии, сохранение и восстановление страховочной копии и аннулирование прежних сессий. В отдельном Asterisk проверено, что звонки блокируются на время обслуживания и возобновляются после него. [Панели администратора](screenshots/admin-backup-restore.png), [эксплуатация](OPERATIONS.md).

Проверен перенос полного `.tar.gz` в свежий Docker-контур: 12 пользователей, 39 сценариев, 36 записей истории, 55 аудиофайлов и вложение. Контрольные суммы восстановленных файлов совпали; запись и вложение доступны через API. Архив с повреждённой контрольной суммой отклонён без изменения свежей базы.
