# Практические занятия диспетчера ДДС

Новый кабинет **«Кабинет ДДС»** тренирует этап после регистрации сообщения оператором 112: обучающийся получает заполненную карточку, проверяет её по сведениям заявителя, исправляет данные и список служб, фиксирует свои действия и передаёт информацию учебным службам. Приём первичного звонка 112 сохраняется в прежнем рабочем месте. Прежний режим «Реагирование службы · ДДС» со статусами своей службы также доступен отдельно.

Основание: «Работа с АРМ-112 для ДДС от ОКр_ГСИ.pdf», разделы о получении карточки, первичном ответе, работе службы и рабочих звонках. Проверка внесённых учебных ошибок — дополнительное упражнение; система не утверждает, что в реальном АРМ ДДС вправе переписывать все поля оператора 112. Учебный исправленный вариант хранится отдельно от исходной карточки.

## Подготовка преподавателем

1. Откройте «Кабинет ДДС» → «Подготовить карточки для ДДС».
2. Назовите набор, выберите количество (1–100) и норматив обработки в секундах. По умолчанию для этого упражнения — 180 секунд; преподаватель может изменить. Это учебная настройка, не официальный норматив службы.
3. Выберите одну или несколько категорий событий; пустой выбор означает все категории.
4. Выберите источник: системные карточки, завершённые карточки ваших студентов или смешанные. В смешанном наборе источники чередуются, начиная с системного. Для студенческого источника учитываются только завершённые, не пропущенные попытки режима 112, доступные этому преподавателю. Пока их нет, система предложит сначала провести занятие 112 или выбрать системные карточки.
5. Отметьте варианты: без внесённых ошибок, опечатки, ошибки в адресных данных, ошибки в службах, смешанные. Выбранные варианты распределяются по набору последовательно. Номера карточек не раскрывают студенту вариант.
6. Нажмите «Подготовить набор карточек». В таблице ниже откройте «Проверить / редактировать»: исходную карточку, название, норматив, эталон и сведения заявителя можно изменить до запуска; эталон показан отдельно. При использовании карточек студентов ошибки в их данных сохраняются в вариантах с ошибками, а вариант без ошибок строится по доступному эталону. Описание студента сохраняется: свободный пересказ не объявляется ошибкой только из-за несовпадения с формулировкой эталона.
7. Нажмите «Составить занятие с этим набором». Режим и задания уже выбраны; выберите студентов и назначьте занятие либо сохраните заготовку. В существующем редакторе занятий новый режим называется **«Проверка карточек и передача службам · ДДС»**.
8. Запустите занятие. Его можно завершить в любой момент: текущие ответы сохранятся и получат оценку, включая невыполненные действия.

Подготовленные карточки принадлежат преподавателю, хранятся в PostgreSQL и входят в резервную копию. Создание набора не назначает его всем студентам. Студенты видят только назначенные им занятия и задания.

## Работа обучающегося

1. Откройте «Кабинет ДДС» и активное занятие. «Следующая карточка» выдаёт случайное оставшееся задание; можно выбрать конкретное назначенное задание из раскрывающегося списка.
2. Сверьте **исходную карточку 112** со **сведениями заявителя**. Исходный вариант остаётся неизменным и доступен для сравнения.
3. Исправьте адрес, описание, данные заявителя, телефоны, число пострадавших и при необходимости класс ЕКП. Службы выбираются вручную из справочника. Автоматический подбор специально не исправляет ошибочные получатели за студента.
4. Выберите вывод: карточка верна, ошибки исправлены или требуются уточнения. Для ошибок и уточнений заполните замечания; всегда опишите действия диспетчера. Не придумывайте неизвестные сведения.
5. Нажмите «Сохранить проверку». Несохранённые изменения сохраняются в этой вкладке браузера и восстанавливаются при загрузке попытки, но перед передачей или завершением проверку необходимо отправить на сервер.
6. Передайте информацию выбранным службам одним из двух способов:
   - **Текстовая симуляция разговора**: укажите получателя, переданные сведения и результат. В отчёте это явно обозначается как текстовая симуляция.
   - **Исходящий SIP-звонок в браузере**: подключите браузерный телефон, нажмите «Позвонить в учебную службу». Asterisk отвечает голосом дежурного. Передайте сведения голосом, завершите разговор, затем зафиксируйте получателя, переданные сведения и результат. Соединение и время ответа подтверждаются событиями Asterisk; простая запись в форме не подменяет SIP-звонок.
   - **Исходящий звонок с SIP-аппарата**: заранее подключите аппарат по инструкции SIP. Нажмите подготовку звонка, наберите показанный временный учебный номер на аппарате, передайте сведения и положите трубку. Интерфейс покажет ответ/окончание через Asterisk; затем сохраните результат передачи.
7. Завершите обработку. В результате доступны исправления, ошибки, службы, время и грамматические замечания. Если занятие активно и есть оставшиеся задания, следующая случайная карточка выдаётся автоматически. Результат предыдущей доступен в раскрывающейся плашке над новой карточкой и в отчётах. После выполнения всех заданий таймер останавливается; выполненное задание повторно не запускается.

«Пропустить карточку» сохраняет отправленные на сервер исправления и останавливает её таймер. При возврате отсчёт продолжается с сохранённого времени; преподаватель видит пропуск и возобновление. Если есть несохранённые правки, сначала сохраните проверку.

## Телефония B → C

Точка B — обучающийся диспетчер ДДС; точка C — учебная служба внутри локального Asterisk. Реальные экстренные номера и внешние телефонные сети не вызываются. Учебная служба произносит приветствие и даёт время для передачи сведений; это голосовая симуляция, не нейросетевой собеседник.

Для исходящего вызова приложение создаёт временный внутренний номер вида `80…`, связанный с конкретной попыткой и SIP-учётной записью студента. Другой студент использовать этот номер не может. После подключения номер одноразово удаляется; запись хранится отдельно для каждого звонка. Номер не является постоянным номером службы.

Аппаратный SIP-телефон подключается по [SIP_PHONE_SETUP.md](SIP_PHONE_SETUP.md). В способе передачи «Исходящий звонок с SIP-аппарата» интерфейс показывает временный номер для набора на аппарате; в браузерном способе приложение набирает его само. У аппаратной линии и браузера раздельные регистрации. Для аппарата на другом устройстве нужен IP хоста в локальной сети и `SIP_PUBLIC_ADDRESS`.

## Отчёт и оценка

Преподаватель открывает мониторинг занятия или «Результаты обучения» → «Разбор». Сохраняются исходная карточка, исправленный вариант, эталон, замечания, история повторных проверок, передачи каждой службе, SIP-попытки и записи разговоров. Доступны существующие фильтры по студенту и датам, группировки, печать/PDF и CSV. В CSV новый режим помечен «ДДС»; добавлены вывод, замечания, переданные службы и способы передачи. Подробная таблица исправлений доступна в разборе.

Первичная оценка: проверка исходной карточки — 10, данные и опечатки — 35, службы — 20, передача информации — 25, время — 10. Проверка данных детерминированная: нормализуются пробелы, регистр и «ё»/«е», списки классов и служб сравниваются как множества. Произвольный пересказ текста может потребовать экспертного разбора. Для зачёта передачи нужны подтверждение приёма и точный эталонный адрес в записи переданной информации; SIP-передача дополнительно требует фактического ответа Asterisk. Отказы и недоступность сохраняются, но не считаются успешной передачей. Необоснованная замена правильных данных снижает оценку. «Требуется уточнение» сохраняет честный вывод, но не считается завершённым исправлением.

Автоматического распознавания разговора нет: содержание аудиозаписи оценивает преподаватель. Оценка грамматики выполняется локальным LanguageTool; при его недоступности отчёт сообщает об этом. Экспертная оценка сохраняется отдельно от первичной.
