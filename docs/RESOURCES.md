# Ресурсы

Заявленные в исходном ТЗ 6 CPU / 32 GB RAM / 512 GB NVMe можно рассматривать как минимальный стенд/MVP при ограниченной AI-параллельности. Они не являются доказанной конфигурацией для 100 одновременно активных пользователей с параллельным CPU-only LLM inference.

Практический старт для пилота 10–20 активных обучающихся: 8–12 CPU cores, 32–64 GB RAM, 1 TB NVMe. Для порядка 100 пользователей: ориентир 16–24 CPU cores, 64 GB RAM, 1–2 TB NVMe; окончательный sizing только после нагрузочных тестов с согласованным числом одновременных AI-запросов. GPU не обязателен для rule-based MVP, но существенно улучшает локальный LLM/TTS.

## Хранение и место на диске

Для учебного контура принят единый срок хранения **6 месяцев**: карточки, результаты, аудит, SIP-записи и аудиовложения. В исходном ТЗ явно указан минимум 6 месяцев для аудита; тот же срок для остальных учебных данных установлен проектной политикой, чтобы не оставлять медиа бессрочно.

Карточка в PostgreSQL занимает мало места по сравнению с аудио. Текущая SIP-запись — моно WAV 8 кГц/16 бит, ориентировочно 0,96 МБ на минуту разговора. Приближённая оценка: `обучающиеся × звонки в день × минуты × 0,96 × дни хранения` МБ. Например, 20 обучающихся, 5 звонков в день по 3 минуты за 180 дней — около 52 ГБ только аудио, без резервных копий.

Приложение ежедневно удаляет данные старше 180 дней; администратор также может запустить очистку вручную. Отдельные backup-файлы требуют собственной ротации и внешнего хранения. Ограничение одного ручного аудиовложения — 50 МБ.
