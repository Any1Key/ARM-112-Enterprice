# Архитектура

## Контуры

Browser -> FastAPI -> PostgreSQL. Redis зарезервирован для очередей/сессий и последующего фонового AI/TTS. Asterisk вынесен в профиль `voip`. AI runtime вынесен в профиль `ai`, чтобы базовый тренажёр не зависел от LLM.

## Почему rule engine является основным

Требования предусматривают сравнение ручного ввода с эталоном, контроль тайминга и регламента. Поэтому объективные поля (тип, адрес, службы, время, статусы) проверяются детерминированно. AI следует использовать для генерации сценариев и семантической оценки свободного текста с обязательной возможностью преподавательской валидации.

## Production-разделение

Рекомендуется: reverse proxy/TLS; app API; worker; PostgreSQL; Redis; SIP; AI/TTS; monitoring; backup target. Для HA одного сервера недостаточно: требование отказоустойчивости узлов подразумевает минимум несколько физических/виртуальных узлов и отдельное резервное хранилище.

## Данные и процессы

app/models.py содержит основную схему и дополнительные таблицы: версии ЕКП/типы, настройки сценариев, материалы, занятия, контекст сессии, события карточки, экспертные оценки и состояния учётных записей. app/classifier.py импортирует XLSX и вычисляет получателей; app/training.py проверяет переходы/индикаторы; app/workflows.py реализует учебные процессы. Основной API и первичная оценка находятся в app/main.py.

Контекст хранит снимок сценария/эталона и ревизию черновика. Повторный request_id не создаёт новую запись. При остановке занятия результаты незавершённых упражнений сохраняются одной транзакцией. Экспертная оценка отделена от первичной. Таблицы добавляются через create_all; необходим переход к версионированным миграциям для промышленной эксплуатации.


## Генерация по ЕКП

`app/scenario_profiles.py` задаёт варианты наблюдаемых событий для всех строк нормативного снимка `app/ekp_generation_manifest.json`. Рабочий API использует согласованные серверные сценарии без LLM; исходные билеты сохраняются через отдельную обработку обстоятельств. Контекст с пострадавшими содержит и текст, и признаки для правил назначения служб. `app/generation.py` добавляет согласованные адрес, ФИО и контакты; фоновые задания остаются в PostgreSQL. Свободная генерация Ollama оставлена только для внутреннего вызова без привязки к поддерживаемому типу ЕКП.

`tools/audit_generation.py` сверяет каталог с исходным XLSX, проверяет все типы на трёх уровнях сложности и сохраняет примеры/метрики. При изменении классификатора неподдерживаемый тип явно отклоняется: автоматическое угадывание профиля не используется.

`app/scenario_locations.py` подбирает город и именованный транспортный объект вместе, затем зону по выбранным обстоятельствам. Сопоставление метро использует границы слова; соседние объекты из нормативных признаков не участвуют. Грузовые станции имеют отдельный каталог. `tools/audit_generation.py` проверяет пары и отсутствие жилых адресов для специальных мест во всём прогоне.
