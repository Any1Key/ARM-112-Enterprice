# АРМ-112 — учебный тренажёр

Локальный веб-тренажёр для занятий по двум разным ролям: оператор 112 принимает обращение и заполняет карточку, диспетчер ДДС получает уже готовую карточку **в свою службу** и ведёт реагирование. Преподаватель готовит сценарии, назначает занятия и разбирает результаты. Это учебный контур: он не подключён к реальной службе 112 и не вызывает реальные экстренные службы.

| Режим | Что делает обучающийся | Что не делает |
| --- | --- | --- |
| Оператор 112 | Принимает учебный вызов, записывает сведения заявителя, выбирает тип ЕКП, проверяет получателей, сохраняет и при необходимости дополняет карточку | Не руководит реальной бригадой |
| Диспетчер ДДС | Решает, принять ли карточку своей службой, последовательно отмечает стадии работ и комментарии, фиксирует контакты и сообщение об ошибке в 112 | Не редактирует исходные поля 112 и не добавляет службы в полученную карточку |

Сценарии создаются из учебных материалов и классификатора ЕКП; доступны занятия, текстовая имитация вызова, дополнительная SIP-телефония, отчёты, экспертная оценка и аудит. [Подробный путь студента](docs/STUDENT_GUIDE.md), [практика ДДС для преподавателя и студента](docs/DDS_TRAINING.md), [единая техническая документация](docs/TECHNICAL_DOCUMENTATION.md), [матрица соответствия ТЗ](docs/TZ_COMPLIANCE.md).

Связь режимов учебная: преподаватель готовит упражнение ДДС из системной карточки или **завершённой карточки своего студента** и назначает его службе. Автоматической передачи каждого текущего обращения из режима 112 в занятие ДДС нет.

## Требования

Установите Git, Docker Engine и Docker Compose v2. Проверка: `git --version`, `docker --version`, `docker compose version`. При первой сборке нужен интернет для Docker-образов, Python-пакетов и голосовых/нейросетевых моделей. Голосовые модели и LanguageTool загружаются при сборке, поэтому первый полный запуск занимает больше времени, чем обновление приложения.

## Быстрый запуск

Описанная здесь версия находится в ветке `dds`. Для первого знакомства достаточно базового запуска без голосовых сервисов:

```bash
git clone --branch dds --single-branch https://github.com/yaro-s-lav/hacka.git
cd hacka
docker compose up -d --build
docker compose ps
curl -f http://localhost:8001/health
```

Откройте `http://localhost:8001`. Если работаете на самом сервере, используйте `localhost`; с другого компьютера для голосовых вызовов настройте HTTPS по инструкции ниже. Первый запуск может быть долгим: Docker скачивает образы и собирает сервисы. Готовность приложения проверяйте по ответу `{"status":"ok"}` от `/health`.

В исходном демонстрационном окружении доступны:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Студент | student | student12345 |
| Преподаватель | teacher | teacher12345 |
| Администратор | admin | admin12345 |

Это учебные пароли; перед доступом из сети замените их и остальные секреты, указанные в разделе «Окружение». Студент видит назначенные задания после запуска занятия преподавателем; если список пуст, это не ошибка установки.

### Первое занятие за несколько минут

1. Войдите как `teacher`. Для режима 112 выберите или создайте и утвердите сценарий, затем в «Занятиях» нажмите «Создать занятие», выберите режим «112», сценарий и студента. Для ДДС откройте «Кабинет ДДС» → «Подготовить карточки для ДДС», проверьте полученные карточки, затем назначьте занятие **конкретной службе** и студенту.
2. Нажмите «Начать занятие». До этого студент не получит карточку. Заготовку можно сохранить без студентов и назначить позднее.
3. Войдите как `student`, откройте «Занятия» или «Кабинет ДДС», нажмите «Следующая карточка» или «Начать», выполните действия и завершите карточку. Выполненное задание в этом занятии повторно не запускается.
4. Вернитесь под `teacher`: откройте «Мониторинг и отчёт» у занятия или «Результаты» для разбора ответа, статусов, времени и звонков. Преподаватель может добавить экспертную оценку.

При базовом запуске доступны карточки и текстовая тренировка. Он включает приложение, PostgreSQL, Redis и резервное копирование; генерация учебных сценариев по ЕКП не требует Ollama. Исходные 96 задач PDF доступны преподавателю в разделе «Билеты и задачи».

Эталонные голосовые ответы служб находятся в `data/service_audio/` и входят в репозиторий. При запуске Docker Compose одноразовый сервис `media-seed` копирует их в общий media-том; поэтому новая установка получает готовые ответы для учебных номеров без восстановления старой базы или аудиозаписей. Записи разговоров, аудиовложения и пользовательские данные намеренно не входят в Git.

### Что важно знать о ДДС

Карточка поступает одной конкретной ДДС; другие получатели видны для координации, но диспетчер их не назначает. После принятия необходимо сохранить по порядку «Начало реагирования» → «Прибытие» → «Проведение работ» → «Работы завершены», с текстом к каждому статусу. Если карточка не относится к службе, требуется мотивированное «Не принята». Открыть карточку нужно в течение 30 секунд после поступления в очередь, внести первый статус и текст — в течение 3 минут от того же момента. Работа после первой записи может идти без ограничения по времени; очередь продолжает отсчёт и при работе с другой карточкой. Об ошибке, обнаруженной по докладу бригады, сообщают в 112 и фиксируют уведомление отдельно: исходную карточку ДДС не правит. [Полный порядок и исключения](docs/DDS_TRAINING.md).

## Запуск со звонками и оценкой

```bash
docker compose --profile voip --profile ai up -d --build
docker compose --profile voip --profile ai ps
```

Для локального запуска, включая звонки, откройте **`http://localhost:8001`**, разрешите микрофон и нажмите «Подключить телефон». В режиме 112 выберите сценарий и «Учебный звонок»; в новом режиме ДДС используйте блок «Учебный голосовой разговор» для доклада руководителю бригады, вышестоящему начальнику или другой службе, чей номер указан в полученной карточке. Номер другой службы используется для проверки допустимости контакта, **реальный внешний вызов не совершается**: звонок идёт на внутреннюю учебную линию и записывается. Сейчас линия ДДС произносит вступление и записывает голос обучающегося, но **не формирует ответные реплики**: полноценный двусторонний голосовой диалог ещё не реализован. Браузер разрешает микрофон на `localhost` по HTTP; SIP подключается к локальному Asterisk через WSS-шлюз. На своём компьютере HTTPS и установка сертификата не требуются. HTTPS на 8443 нужен при доступе с другого компьютера по IP или DNS-имени.

При работе с другого компьютера задайте в `.env`:

```dotenv
ARM_HOST=192.168.1.100
SIP_PUBLIC_ADDRESS=192.168.1.100
```

Замените адрес на доступный студентам IP сервера. `ARM_HOST` также может быть DNS-именем; порт и протокол в него не включаются. Перезапустите:

```bash
docker compose --profile voip up -d --force-recreate app asterisk turn gateway
```

Адрес интерфейса: `https://192.168.1.100:8443`. Caddy использует локальный центр сертификации. Установите его корневой сертификат в доверенные на компьютере студента, иначе браузер может блокировать SIP/WebSocket:

```bash
docker compose cp gateway:/data/caddy/pki/authorities/local/root.crt ./arm112-root.crt
```

Для связи между компьютерами откройте на сервере TCP 8443, TCP/UDP 3478 и UDP 10000–10100. Приложение по TCP 8000 нужно только при прямом HTTP-доступе; интерфейс Asterisk TCP 8088 доступен также через HTTPS-шлюз. [Проверка и настройка аппаратного SIP-телефона](docs/SIP_PHONE_SETUP.md); для приёмки ДДС он не обязателен.

## Окружение

В репозитории есть `.env` для демонстрации и `.env.example` как полный шаблон. Они содержат учебные значения, а не секреты действующего защищённого контура. Перед доступом из сети замените `POSTGRES_PASSWORD`, `SECRET_KEY`, `ADMIN_PASSWORD`, `TEACHER_PASSWORD`, `STUDENT_PASSWORD`, `ASTERISK_AMI_SECRET` и `TURN_SECRET`. Не коммитьте действующие пароли. `BACKUP_DIR` задаёт каталог полных резервных копий; по умолчанию это `./backups`.

Для генерации отдельного секрета:

```bash
openssl rand -hex 32
```

Используйте разные значения для каждого секрета. Пароль PostgreSQL должен подходить для URL подключения; шестнадцатеричная строка подходит. На уже запущенной базе изменение `POSTGRES_PASSWORD` в `.env` не меняет пароль пользователя PostgreSQL; изменения паролей исходных аккаунтов также не заменяют существующие учётные записи. На новом сервере задайте значения **до первого запуска**; существующих пользователей меняйте через кабинет администратора.

## Обновление

```bash
# Сначала сохраните копию базы.
docker compose exec -T backup sh /backup.sh
# Если вы редактировали включённый в Git .env, сохраните свои настройки вне проекта.
cp .env ../arm112-env.saved
git pull --ff-only
docker compose --profile voip --profile ai up -d --build
docker compose ps
curl http://localhost:8001/health
```

Если Git сообщает о конфликте локально изменённого `.env`, сначала сохраните его, восстановите только этот файл из Git командой `git restore .env`, выполните `git pull --ff-only`, затем верните нужные настройки из сохранённой копии **до пересоздания контейнеров**. Используйте те же профили, что при первоначальном запуске. После обновления интерфейса нажмите Ctrl+F5.

## Управление и диагностика

```bash
docker compose logs --tail=100 app
docker compose --profile voip logs --tail=100 voice asterisk gateway
docker compose --profile ai logs --tail=100 ml grammar
# Остановить контейнеры, сохранив данные:
docker compose --profile voip --profile ai down
# Запустить снова:
docker compose --profile voip --profile ai up -d
```

Данные базы, аудио и настройки SIP хранятся в Docker-томах. `docker compose down -v` удаляет тома и данные; для обычной остановки его не используйте.

## Карточки и перенос данных

При первом запуске импортируются классификатор ЕКП и 96 задач из исходных материалов, создаются демонстрационные пользователи, 4 исходных сценария и **32 постоянные карточки практики** (24 базовые и 8 для новых процессов). Каталоги лежат в `data/scenarios/practice.json` и `data/scenarios/workflows.json`. Они устанавливаются и на новой, и на существующей базе без дублирования и без перезаписи правок преподавателя.

Сценарии преподавателя, занятия, попытки, пользовательские данные и журнал работы находятся в PostgreSQL. `git clone` и `git pull` **не переносят** их между серверами. Для переноса используйте полную резервную копию: базу, аудио и вложения. Копия создаётся каждые 23 часа; администратор может запустить её вручную и скачать через «Мониторинг» → «Скачать всё». На другом сервере полный `.tar.gz` восстанавливает пользователей, карточки и историю при совпадающих версиях приложения. Отдельные «Скачать БД» / «Восстановить БД» затрагивают только PostgreSQL. `.env` нового сервера настраивается отдельно; после переноса войдите заново и переподключите SIP-телефоны. Проверка копии без замены рабочей базы: `make verify-backup`. [Порядок эксплуатации и восстановления](docs/OPERATIONS.md).

Студенту в обоих режимах нужно назначение преподавателя; для ДДС дополнительно выбирается конкретная служба. Отдельное учебное SMS может назначить карточку 112 вне занятия.

## Возможности и границы

В карточке 112 есть структурированные опросные карты, дополнения после регистрации, признаки пострадавших, оформление вызова без контакта, связи повторных обращений, напоминания, помощь старшего специалиста и учебные SMS. Преподаватель задаёт эталон ответов; после попытки он видит автоматическую и экспертную оценку. [Порядок демонстрации и границы интеграций](docs/HACKATHON_DEMO.md), [звонки и полный отчёт](docs/CALLS_AND_REPORTS.md).

Активный XLSX выбирается через `CLASSIFIER_FILE` (по умолчанию `046_24`). Поддерживаются структуры с 99 и 90 колонками; простое добавление файла в `source_materials` не переключает классификатор. Заказчик пока не подтвердил приоритет `046_24` и `046_11` при расхождениях. Полного адресно-территориального и телефонного справочника ДДС нет: преподаватель проверяет получателей учебной карточки перед назначением. Изменения преподавательской оценки сохраняются, но автоматическое дообучение модели по ним пока не реализовано.

Дополнительные инструкции: [работа студента](docs/STUDENT_GUIDE.md) (краткая версия есть в «Памятке»), [занятие ДДС](docs/DDS_TRAINING.md), [внешний SIP-телефон](docs/SIP_PHONE_SETUP.md), [произношение русских номеров](docs/PRONUNCIATION.md), [API](docs/API.md).
